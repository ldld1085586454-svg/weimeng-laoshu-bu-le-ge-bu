# v0.9 道具与对局流程实施任务

目标：在已验收 v0.8 算法上交付 B（道具）及 C（本地会话/模拟奖励）的可运行工作版本；不宣称完整商业游戏。

## 已批准边界
- v0.8 的 `src/*.js` 逐文件摘要锁定，不修改生成、验解、求解和旧内核。
- 新增 `src/play/` 处理独立暂存区、移出前三张、撤回和实际洗牌映射；新内核与旧内核进行无道具对照。
- 单局三道具各一次为既有工作基线。暂存任意取回、普通主区撤回、消除后/道具后清除撤回资格、洗牌不含暂存均标注候选。
- 侧堆/暂存撤回和复活效果仍未绑定：返回明确错误，不能启动模拟领取。原有功能并未从总范围删除。
- 奖励只用 `development_mock`。取消/失败/分享返回不发奖；不接真实广告，不虚构日额度。
- 存档仅为诊断的事件记录导入/重放，不增加正式继续游戏入口，也不自动恢复旧局。
- 数字牌面、开发条及领取模拟弹窗均为联调UI，不是最终原作美术。

## 实施步骤
1. 运行 v0.8 基线测试，保存结果。
2. 先编写道具及会话回归测试，确认缺失功能导致失败。
3. 实现纯状态变化和守恒校验；实现 commandId、roundId、版本、奖励token绑定和事件记录。
4. 构建单文件可操作HTML及微信工程；桌面/手机比例浏览器操作测试。
5. 原 67 项测试、新增测试、随机道具序列、完整回放、字节一致性和压缩包解压验收。

## 验收要求
有反例及原始日志；所有输出单独标明未验证的历史规则、真机和平台广告；工作包不覆盖旧版本。
