## 已确认的两项实际扩展

### 1. 微信账号、独立后台和云进度

推荐：沿用 JavaScript/Node，不绑定付费云厂商。现有本机开发服务保留，增加独立的远程接入契约和可运行服务，先通过真实本地 HTTP 集成测试。使用 SQLite 事务作为单实例可部署基线；公开部署、生产域名、账号资质和凭据配置仍需后续授权与实际验证。

客户端新增微信 wx.login + wx.request 适配，临时 code 只送配置的 HTTPS 自家服务；后端交换身份。AppSecret、session_key 不进入客户端、公开仓库或日志。未配置时明确报接入未完成，不静默用本地账号冒充线上。

接口：认证/会话、bootstrap、start、进度读取/保存、奖励 offer/观察/权益、settle、换装、预设弹幕。用户归属来自会话。云进度使用版本比较更新并验证原 ticket 与重放日志；另一设备冲突提示，不覆盖新进度。服务端结算事务对同一 ticket 幂等，同日模式贡献去重；榜单分页且只统计已接受结算。

真实广告 onClose 只能证明客户端观察，不能当不可伪造的服务端验证。奖励权益必须绑定账号、ticket、offer、道具、棋盘版本与有效期，服务端验证来源未明确之前真实奖励封闭。本地集成测试使用明确的测试验证器，不能冒充平台真实广告。分享回流不发奖。竞速荣誉没有独立可信计时之前不能称可信线上排名。

影响：客户端与服务端各增加一个明确模式，不再把模拟开发身份当微信身份；服务可独立部署但本轮不购买、开通、生成凭据或公开部署。

### 2. 普通局继续挑战

推荐：新增首页“继续挑战 / 重新开始”，只恢复同一用户、服务、当日有效 ticket 的原局。保留牌面、暂存、道具额度与已累计有效时间；离线/后台时间不计。首次失败尚未做复活决定也回到原失败选择，不自动认定失败。已有 EARNED 奖励及终局 outbox 优先恢复，不能被新局覆盖。

旧规格刻意不恢复普通 PLAYING，因此这是明确变更。过期、损坏或身份不符的记录不恢复；重新开始需确认放弃现局且清理其可续局记录。云冲突不自动择一覆盖。
