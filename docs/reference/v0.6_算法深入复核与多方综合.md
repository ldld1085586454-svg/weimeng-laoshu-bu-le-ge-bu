# 《羊了个羊》2022微信版：算法深入复核与多方综合 v0.6

日期：2026-09-18。对象：v0.5 `ASTRA_DEAL_V1`，不是重新设计玩家模式。
状态：研究、独立有限验证、工程设计增补；不是完整生产生成器或微信可玩包。

## 1. 结论先行

v0.5 的“拓扑取牌路线＋安全图案序列”构造，在明确前提下能证明初局至少有一条无道具解。这部分没有被本轮反例推翻。

不足不是“没有解”，而是尚未证明生成内容在策略、信息和容错方面接近目标版本。上一版已经提出独立回放、变异、多策略试玩和非均匀采样限制；本版不将这些重新包装为首次提出，而是补齐可执行的反例、精确指标及取舍边界。

本轮新增实质内容：

1. 用两种18牌布局证明同一条高压力答案不决定关卡最低容量或决策复杂度。
2. 用精确概率证明随机机器人通过率低，可以发生在所有牌明摆着的简单局面。
3. 构造观察相同却要求相反首步的两个有解残局，拆开“全知有解”和“可见信息能推断”。
4. 给出固定牌面、无道具情况下只用取牌集合表示搜索态的证明、递推及独立对照程序。
5. 审查社区来源独立性、胜利定义和观察索引泄漏风险，明确哪些结果不能直接当原作证据。
6. 将生产方案收敛为离线候选生产和多维评价，不增加游戏难度选择、提示、透视或实时改牌。

## 2. 多方材料不是多份独立证据

### 2.1 原作者采访：有历史价值，不等于数学规格

2022-09-19刊出的采访中，张佳旭否认网上所说的算法控制，并解释过被遮挡导致的“只剩少数牌”错觉；广告段落讲到视频广告及去掉横幅的选择。[S01]

这里只能记录受访者当时如何表述。不能由此推导所有初局必有无道具解、洗牌保证成功、底牌独立均匀、每日同一牌局或具体人均广告收入。

### 2.2 鱼了个鱼：牌池与几何构造参考

所读2022固定提交的 `initGame` 先按种类和组合数补齐数量，然后打乱并分配到侧堆和层级区。[S02]

可以参考数据流。仅有各类数量为3的倍数不构成“可到达的通关路线”的证明。其社区额外功能、道具次数及调试设置不进入原作范围。

### 2.3 solvable-sheep-game：初局答案可以从构造规律推出

固定2022提交按同类每次六张加入数组；`checkCover` 只把后面的重叠牌当作前牌的阻挡。[S03]

由代码可推导：从数组末尾倒着取，下一张没有尚未取走的更后项阻挡，同类六张分成两个三消。因此在本段规则内存在明显构造答案。这个推导只针对生成的初局，不扩展到修改坐标后的洗牌残局。

启示：能构造有解与能构造多样、难度适当的关卡，是两种不同能力。也不能把生成数组索引直接暴露给“模拟玩家”却声称它不知道答案。

### 2.4 DI-sheep：强化学习方法可参考，环境目标不能照搬

README明示其React前端主要参考StreakingMan，因此两者不构成两份独立的原作还原证据。[S04]

本轮真正固定并重读的环境文件提交是 `45773344521145eca5b040e8ca3437f95137b6f0`，文件最后修改日期2023-02-12；不是2022年9月客户端。[S05,S05M]

静态发现：

- 第10级采用10类、每类9张，再加入2张不同图案，总量92。按每次只消3张的规则，不可能把92张全部三消完。
- `step` 在 `cur_item_num==0` 时先给结束奖励，没有同时要求槽内清空。因此它的结束条件不等同于我们验证器要求的“全部牌已消除”。
- `_get_obs` 按生成场景的原索引输出观察行，而生成时按图案分批。即使隐藏牌的显式图案字段被遮掉，行号仍可能携带类型规律。这是静态可见的信息泄漏风险；未运行训练模型，不能断言模型实际利用了它。

本轮脚本独立复算92张数量并重放同类批次的逆序序列，末尾余2张；这是窄范围数学镜像，不是启动该仓库运行的测试。

结论：可以借鉴“构造环境、观察模型、动作掩码、策略评估”的分层思想；不能拿此环境的通关率替代严格全消规则，更不能把其级数、牌数或规则认定为原版。[S05]

### 2.5 NB-Dragon：求解器参考，而非原作生成器

本轮固定读取提交 `1d6ad309dc0ceb8dcff204ed3cffd7aae092fc81` 的 `business/SheepSolver.py`；日期2024-11-30。[S06]

其核心类递归调用取牌和回退，由控制器生成候选，并有时间限制和进度预期的提前停止；没有完成时结果接口可以返回 `None`。因此 `None` 不能直接解释为无解。这是对所读控制流的结论，不是对所有依赖类的完备性审计。

用途：参考路径记录、回退、限时、状态指纹的工程组织。正式判定仍需三态：有解证据、穷尽无解、未知。

### 2.6 论文带来的补充，而非原作规则

2016年AIIDE的推箱子研究把保证有解的生成与用户研究校准的难度特征结合；2024年AIIDE的信息度量研究把玩家知识/策略纳入难度定义；同年另一项逻辑格谜题研究通过用户研究检验求解器指标与主观难度的关系。[S07,S08,S09]

本轮阅读范围是出版方摘要和元数据，未阅读其完整PDF或复现实验。它们提供的是“分别验证可解性和玩家体验”的方法依据，不提供羊了个羊的参数，也不能据此断言搜索耗时与真人难度总是相同或总是无关。

## 3. 三个实际跑过的反例

全部使用我方合成数据，非2022历史关卡。详见 `verification/audit_report.json`。

### 3.1 同一条答案，不同的真正容量需求

同样的18张序列：`A B C D E A A B B C C D D E E F F F`，沿该序列三消后的最高槽占用是6。

|合成布局|保留路线最高稳定占用|精确最小槽容量C*|决策特点|
|---|---:|---:|---|
|18张全部可取、全部明牌|6|3|可以直接同类三张一组取完|
|18张单一强制侧堆|6|7|每一步仅一张合法牌，无需作选择|

“最小容量”仅为离线分析；实际游戏仍是七格，不新增三格模式。

程序遍历开放布局全部262,144个取牌集合；强制栈只有19个可达集合。结果分别证明C*=3与C*=7，并输出可独立重放的路径。

这里同时否定两个错误捷径：答案压力高不等于没有简单解；最低容量高也不等于必须思考很多。

### 3.2 随机通过率低，仍然可以是简单关卡

对前述全部明牌18张局面，以“每次从可取的具体牌中等概率选一张”为策略，在七格规则下精确计算通关概率：

`2005 / 38896 = 0.05154771698889346 ≈ 5.1548%`。

这个概率不是抽样估计，而是对计数状态的递推；求和权重为该类尚存牌数除以全部尚存牌数。任何始终完整取完一组三张再换类的策略都能通关。

所以若生成器只最小化随机策略通过率，就可能错误地把明牌配对局当成高难度。这个数不能写成真人通关率或原作通关率。

### 3.3 两个都“有解”的局面，可以让可见信息玩家无法保证选对

设当前槽为 `A A B C D`；有左右两堆，每堆5张，只能看见和取走顶牌，左右顶牌分别是B、C。完整布局如下，按上到下列出：

|测试世界|左堆|右堆|唯一仍可无道具通关的第一步|
|---|---|---|---|
|世界1|B A B D D|C E E E C|取左B|
|世界2|B E B D D|C A E E C|取右C|

两者初始可见图案、堆长度、槽内容相同，隐藏图案总多重集合也相同。总量计入槽后均为5类各3张。

世界1错取右C后，槽为 `A A B C C D`；两堆顶牌B、E均不能立即三消，下一张必失败。世界2错取左B同理。

分别知道全部底牌时两局都有解；只获得相同观察和历史时，确定性策略首步必须相同，至少在一个世界失败。人为给予两个世界各1/2先验时，任何策略首步成功概率上界是1/2；这不表示实际游戏有50%的盲猜率。

这种残局可以由相同的5张外露前置牌先取入槽而到达，不需要破坏图案守恒。测试模型“仅顶牌可见”不冒充原版所有半遮挡牌的实际可辨认程度。

结论：需要记录信息不足造成的风险，不能把它全解释成智力/策略难度。也不能未经用户允许把原作改成全信息解谜。我们只测量和校准，不自行增加提示或透视。

## 4. v0.5证明应当如何准确使用

再次穷举8类、各3张，65,536个已分配数量向量中，38,815个合法非终态都存在安全后继，与上一版一致。

证明前提是生成时可以从未分配图案池自由选择下一类，并将它放在已生成合法取牌路线的下一位置。它不是任意既有残局的恢复证明。

“槽中有一对且总体还剩第三张”不代表“第三张目前可取”。第三张可能在要多取两张才能翻开的地方。本轮两个隐藏世界正说明可达性和图案数量不能混为一谈。

保留以下结论：路线合法＋类型序列安全＋最终绑定快照的独立重放，能证明至少一条初局无道具解。

不扩展到：所有路径、洗牌后、移出后、每个半途状态、原厂设计、真人能辨认答案。

## 5. 精确搜索的新简化与证明

本节仅对固定图案、固定遮挡、无道具、立即三消且不依赖槽顺序的子问题成立。

设M是本轮已经从牌面取走的牌ID集合，T_t是类型t的牌ID集合，c0_t为开始分析时槽内该类张数。

`c_t(M) = (c0_t + |M ∩ T_t|) mod 3`。

因为每次消除只减3，类型的槽内余数完全由M决定。遮挡能否取也只取决于M。故无需将可从M推导的计数重复放入搜索键。

定义q(M)=sum_t c_t(M)，F为全取集合。在配额保证最终清空的前提下：

`D(F)=0`

`D(M)=max(q(M)+1, min_{i ∈ 可取(M)} D(M∪{i}))`。

解释：当前非终态必须留出下一张的空间；在所有合法下一步中选可达到最小峰值的路径。途中稳定槽若达到容量即失败的约束，会通过下一非终态的q+1体现。独立按实际入槽/三消顺序重放再次检查。

D(empty)是精确最小槽容量。若不平衡、约束有环等输入不合法，应返回输入错误，而非伪造一个大难度分数。

程序还将30个不同的9牌抽象DAG测试夹具（每个3类各3牌）在5种容量下，与不使用位掩码/缓存的列表递归实现比较，共150次，结果一致。这些只是小型测试棋盘，不是原版规模的单局。

最坏状态量依然随N指数增长。该研究脚本限制N≤20；不是能处理原版规模的性能保证。正式大局面使用预算化搜索，UNKNOWN必须保留。不能把小局面2^18的完成时间外推到数百张。

### 5.1 道具不能使用这个压缩态

两槽 `A A B C D` 与 `B C A A D` 的计数相同，但移出前三张后分别留下 `C D` 与 `A D`。对道具未来而言并不等价。

完整道具求解至少要记录有序槽ID、暂存/侧堆顺序、可撤回历史、剩余次数、图案版本和随机分支语义；本轮没有实现或测试这一完整空间。

## 6. 更新后的难度档案

每个候选保存指标向量，而不是一个冒充原作的百分比：

|指标|解释|不能误用为|
|---|---|---|
|可解性证据|合法通关路线与独立重放|真人容易通关|
|最低容量上下界|有证据的最优压力范围|绝对思考难度|
|有效选择与分歧|可选动作中有多少导致不同后果|简单计数的按钮数量|
|局部可解选择比例|在已分析状态中，哪些首步仍可解|被UNKNOWN污染的精确概率|
|可见信息缺口|隐藏变化是否改变正确决策|所有隐藏都不公平或都很难|
|多策略分布|随机、三消/配对、记忆、有限推断各自表现|真人通关率|
|道具作用与容错|指定状态和次数下作用前后的差异|道具一定有效或必需|
|体验节奏|已消除比例、失败前无反馈步数、关键决策分布|后台调高广告触发率|

如一个状态有d个候选，证明a个可解、b个无解，u个未知（d=a+b+u），则可解首步比例只可写区间 `[a/d,(a+u)/d]`，不能把未知算成无解。

可在报告中保存“策略差异”：明牌贪心明显优于随机，通常代表可利用的配对信息；全知求解器明显优于只见顶牌策略，可能来自信息缺失，但也可能来自策略能力不足。后者只有观察等价反例等严格证据才可证明不可辨认，不从普通性能差距直接断言盲猜。

## 7. 收敛到可执行的生产路线

建议内部版本 `ASTRA_DEAL_V1.1`，不改变v0.5的基本有解构造，不新增玩家功能。

`锁定模板/规则/配额 → 采样合法路线及安全类型串 → 独立重放 → 局部图案交换与多样性采样 → 重新证明 → 快速检测捷径 → 多观察策略评价 → 分层保留候选 → 真人/历史体验校准 → 固化发布`。

v0.5已提出交换并保留原证据的机制；本轮补充两种明确路径：

- 基线变异：交换后原证据仍能重放才保留。高吞吐但候选受原路线限制。
- 换证据变异：允许旧路线失效，但必须在预算内找到新证据且独立通过；找不到不是无解，只是当前候选不能进入已验证池。

纯随机配平可作为离线对照组，不能未经验证直接投放；全范围几何重排与难度自适应并不自动进入还原范围。

只保留求解器快速找到答案的牌局，会偏向该求解器容易证明的分布；只保留某一条构造答案，也存在生成路线偏好。多样化路线、多个策略、留出不同布局进行测试能缓解，但不能声称重建了原厂概率分布。

## 8. 模拟玩家的防泄漏要求

运行内核需要知道底牌；模拟玩家不应因此得到底牌。分开两个输入视图：

- 真值视图：完整图案/几何，供回放、全知求解与误差归因。
- 观察视图：与屏幕和合法记忆一致；隐藏图案为未知，不含答案、生成顺序、未公开种子、可反推类型的内部索引。

给策略的行顺序和不透明ID必须独立于类型/证据路线。视觉层级是屏幕可观察信息，不需要隐瞒，但禁止附带同类生成批次等不可见标签。

非干扰测试：两状态可见信息、历史及策略随机流相同，仅未见底牌不同，则策略此步输出必须相同。基于未来模拟的策略不得偷用真实隐藏配置；需要预测时只能从声明的可见信息条件分布中采样。

本轮合成双世界验证了观察等价与正确动作相反，并未实现完整的生产观察适配器，不能写成防泄漏验收已全部完成。

## 9. 道具、广告与生成器边界

广告授权/领取机会、道具效果、牌局生成是不同模块。按现有原作范围记录，不增加新收费入口。

可离线评估：一次移出/撤回/特定洗牌策略在某残局上的改善。前提是该道具的实际规则和次数已经绑定；未知效果只能标未测。随机洗牌有利的可能性不能等同于每次洗牌保证成功。

不得通过本轮研究填入“原版看几次广告就放水”的数值；目前没有此证据。也不把“保留有解答案”偷偷做成看完广告后改底牌、自动三消或强行复活。对局快照在既有合法操作之外不变。

不主动改变原作的广告额度、分享流程、是否续局或挑战分配策略。当前平台实现约束与历史可见行为仍分别管理。

## 10. 这次确实完成与没有完成的事

已完成：重读社区关键函数、历史采访及3篇出版方论文摘要；新写独立有限模型脚本；两种18牌布局精确最小容量、随机策略精确概率、双世界隐藏信息反例、150次列表/位掩码对照、65,536向量再核验、输入与回放错误检查。

没有完成：官方生成器/完整历史每日关卡库的取得；完整社区仓库逐行审计；生产关卡生成器和大规模求解性能测试；DI-sheep/NB仓库运行或模型训练；原作客户端/微信工具/手机真机测试；真人难度和广告收入校准。

这些测试加强的是算法设计可信度，不把还原完成度虚报为100%。原厂难度的真实分布、全部历史布局、每日/重开取样方式、广告额度和洗牌边界仍需来源补证。

下一编码重点应是：让生成器与独立验证器输出可追溯快照，并使用这些反例作为回归夹具；不是先把一个单一机器人通过率调低，再宣布还原成功。
