日期：2026-09-18  
文件性质：技术开发文档的范围依据；不是完成版实现规格，也不是开发启动授权。

## 1. 用户已确认的目标

完整还原“2022年爆火时期的微信版”，使用微信开发者工具开发，自写代码。还原对象包括玩法、玩家可见流程、社交展示与当时的商业化入口；不擅自增加或删除系统。

2022年9月为优先历史取证窗口。用户并未指定内部客户端构建号，研究也未取得该构建号；不能把“历史阶段已确认”写成“已拿到某个完整官方版本”。

2023年的羊羊大世界、后续iOS星球内容不在本项目目标内。实时对战、充值商城、体力、通行证、宠物养成、自动救局等也没有获得新增授权。测试日志、模块拆分等可以作为内部工程措施；它们不得暗中改变玩家可见行为。

## 3. 本次新增证据：不能写死广告/分享分配表

2022-09-15的白鲸出海留存图显示三种道具的视频领取按钮。[S09] 同日运营研究社文章的留存图显示三种道具的分享领取按钮。[S21、S22]

可确认：这个历史资料窗口同时留存了两类界面。不可确认：是否由同一账户遇到、能否自选切换、是否先分享后广告，或是否属于同期更新/条件差异。以上解释都只是待调查的可能性。

上观新闻对部分辅助机会使用重新洗牌的概称。[S20] 不能把这句话变成另一个道具，也不能覆盖原作三个独立按钮。不同来源不一致时保留冲突，不选一条方便实现的说法冒充结论。

## 4. 历史复原的验收记录

每个行为按“历史来源 → 日期与平台 → 前置状态 → 操作 → 可见结果 → 次数变化 → 异常边界 → 开发对照”记录。截图只能证明截图直接显示的内容；操作序列需要带前后状态的录屏或其他可重复证据。

今天打开的更新版不能直接用来确认2022行为。某日的首页外观也不能与另一日不同界面的控件随意拼装。[S08、S11]

内部关卡算法、原始概率及服务端配置尚未取得。独立实现必须披露哪些输出已匹配、哪些内部机制未知，不把合理推测称为原算法。

## 5. 文档推进次序

先完成《玩家流程与页面清单》与《核心规则/道具状态表》，把取牌、三消、失败、复活和广告/分享返回接在同一套原作流程中。然后补齐《日更/排名/社交/装扮规则》，再写模块接口、数据结构、测试用例与开发分工。

以下六组是近期取证重点，不是默认答案：第七张形成三消的时序；移出对象及重新取回；消除后撤回；洗牌实际范围；复活与移出是否共享资源；分享/视频入口的触发与额度。

平台接入和素材使用另设发布核验项，历史截图只作研究证据，不视为已获商用许可。本次未审定当下微信上线要求。
