# v0.8 修复闭环与验收记录

日期：2026-09-18。本报告记录本轮实际修改与运行。属于实现者自查，不是另外一名模型、第三方机构或人工专家已签字的独立审计。

## 1. 修复闭环

|事项|根因|变更|新增验证|
|---|---|---|---|
|R1|runtime.createRound 只查类型字符串，没有逐类型配额约束|schema.js 对每类图案检查三的倍数；运行、独立回放、求解均在入口调用基础结构检查|A、A、B 在进入对局前拒绝；空牌局、无效 schema/ID/图层、配额错误、坐标超限等输入矩阵|
|R2|replay 与 runtime 对 layoutId、stackId、坐标限制等接受范围不一致|共享字段/配额契约，保留独立几何和三消实现；新增 verifyRelease 和 CLI/构建门禁|缺失 layoutId 即使凭据 JSON 摘要更新也被拒绝；修改 witness 后构建失败且不覆盖旧联调包|
|R3|新 ID 只拼接原 ID 和洗牌次数，没有记录实际新映射|Portable SHA-256 内容摘要 + 根 ID/会话 ID/操作 revision/洗牌次数分离；洗后编号含摘要|不同置换得到不同摘要；相同置换可重现；相同内容不强制重新洗；槽牌和已取牌不变|
|附带保护|注入 shuffle 接口可能返回非置换|核对长度和图案多重集合；不通过则抛错，原输入保持不变|非数组、漏牌、同长度替换图案及数量变化均被拒绝|

新增 pure JS 文件：`content-hash.js`、`schema.js`。新增 Node 离线文件：`release.js`。
运行域只分发 content-hash/schema/layout/runtime 四个核心文件；不导入 Node crypto，也不把生成器、答案或求解器混入正常运行依赖。
开发联调页故意带 witness 用于验收，不能直接当作正式客户端发布。

## 3. 压力与独立对照

两批相互不同的种子各 1,000 局：合计 **2,000 局、1,019,520 张、2,000 份不同快照**。逐份独立回放通过；另抽 100 局使用真实运行内核完整走到 WON。
三种测试规模为 270、540、720 张，全部是合成模板。不是 2,000 种原厂地图，不代表全部原版状态。

旧套件含 100 个小局面 × 5 种分析容量的 500 次求解对照；新增压力脚本含 120 个主区/侧堆混合小局面 × 5 种容量的 600 次对照，全部一致，新增组无 UNKNOWN。
这些对照覆盖固定牌面、无道具子问题，不能扩大为含全部道具的求解证明。

哈希 110 个输入字符串与 Node crypto 结果一致，包含 Unicode、孤立 UTF-16 代理字符、55/56/64/65 字节填充边界、长串和确定性随机串。
旧 270/540/720 三份样例重新生成后，牌面、关卡编号和通关路线一致；旧 receipt 仍能过发布门禁。

详细见 `reports/benchmark.json`、`reports/additional-stress.json`、`tests/contract-hardening.test.js` 和 `tests/release-pipeline.test.js`。

## 5. 工程边界未变

本版没有重写 ASTRA_DEAL_V1.1 的路线/图案选择逻辑，修复集中在合法输入和身份一致性。
机器人难度度量仍需校准，现有候选筛选不是原作难度认证。移出、撤回、复活、广告/分享、会话恢复和社交系统依旧属于后续整合范围，不作虚假完成声明。

`hashSnapshot` 标识不可变牌面，不包含 taken/rack/revision；只用此摘要保存整个游戏进度是不正确的。
摘要没有密钥，不能作为玩家成绩真实性或防作弊证明。
`roundId` 由调用方提供；null 只是开发期未绑定，不是全局唯一会话 ID。
