# 道具与单局流程 v0.9：交付与验收

## 交付范围

本轮在用户认可的 v0.8 算法之上增加道具和单局会话；12 个原算法源文件的摘要全部保持不变。完整包包含旧算法、新增模块、联调HTML、新微信工程、测试与历史资料，不用拼接补丁。

已实现：移出前三张到暂存、暂存取回与三消、普通主区撤回、候选洗牌、单局三道具次数、领取准备与明确的模拟结果、重复请求/重复奖励/跨局回调防护、诊断记录重放、开始/对局/领取/失败/通关交互。

复活效果仍未绑定；侧堆及暂存撤回也未宣称还原。完整首页、社交、资源、动效/声音、真实广告和在线服务不在本轮完成项。

## 新增复核中修复的两个问题

1. `undefined`可选字段先参与签名、导出却被JSON删除，导致恢复后同一请求被误判为异载荷。现在先规范化JSON再签名；回归测试先失败再通过。
2. 会话层对tileId长度的限制比冻结的关卡加载器更窄，导致合法长ID加载后不可取。现与旧牌ID/图案字符串的契约一致；命令ID和roundId仍有独立长度限制。

首次道具测试还发现“已耗尽”与“暂存占用”同时满足时拒绝码优先级不一致，已统一先检查局内额度。`reports/`保留了红灯及迭代记录，它们不是最终测试结论。

## 不得误报的能力

内存状态一次提交不等于数据库跨设备事务；本地checksum不等于防作弊；模拟完成不等于真实广告验真；诊断导出不是原作已经确认的续局入口；类型声明/接口桩不等于真机。没有设置每日广告上限，没有猜测复活如何清槽，也没有偷偷增加商城或实时对战。

## 使用

解压后打开 `道具与对局联调_双击打开.html`；微信开发者工具导入 `wechat_game/`。日常验收运行 `一键验收.cmd`；本轮混合压力运行 `npm run play:stress`。完整命令、候选来源和实际接口见README及 `接口与候选规则_v0.9.md`。
