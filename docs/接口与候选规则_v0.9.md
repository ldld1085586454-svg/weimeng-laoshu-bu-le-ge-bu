# 接口与候选规则 v0.9

## 1. 接续与冻结

目标是2022年爆火时期微信版。生成器等12个旧源文件的清单以 `v0.8_algorithm_frozen.json` 为准，摘要测试保证未经修改。新包不重新设计已认可的有解构造。

v0.4 的 CT 是规划时的契约索引。本轮新增的实际 JS 接口列在下文；不要声称 CT01—CT26 都已实现。新模块置于 `src/play/`，不更改旧 `src/index.js` 聚合入口。

## 2. 规则来源及采用范围

## 3. 实际可调用接口

`src/play/board.js`：

```js
createPlayRound(deal, roundId)                 // 通过旧加载器验证初局，新增buffer/undo
legalTiles(board)                            // 主区/侧堆+候选暂存的合法取牌ID
pickTile(board, tileId, profile?)             // {ok, code, state, events}
canAssist(board, kind, profile?)              // null或明确拒绝码
applyAssist(board, kind, profile?, labels?)   // 仅效果，不代表有领奖资格
checkRound(board)                            // 守恒/遮挡/清除计数/稳定终态
```

`src/play/session.js`：

```js
createSession(deal, { roundId, rewardMode: 'development_mock' })
dispatch(session, command)                    // {ok, code, session, events, replayed}
exportSession(session)                       // 诊断JSON字符串
restoreSession(text)                         // 重新执行记录；不直接相信存档里的终态
fingerprint(session)                         // 内容一致性摘要，不是鉴权签名
```

命令公共字段为 `id/roundId/expectedRevision/type`。本轮仅三种类型：

```js
{ type:'PICK', tileId }
{ type:'REQUEST_ASSIST', assist:'move'|'undo'|'shuffle'|'revive' }
{ type:'REWARD_RESULT', token, result:'completed'|'cancelled'|'failed'|'share_returned', permutation? }
```

会话 revision 和棋盘 revision 分离：领取准备/取消也会更新会话版本，但不修改牌局。每次成功副作用只提交一个新会话对象。持久化与联网数据库事务尚未实现，不得把这一内存保证说成跨设备恰好一次。

同一ID同一载荷返回已确认结果，**不重放事件、不回退到旧状态**。同ID异载荷拒绝；旧revision拒绝；旧roundId拒绝；已完成token拒绝重新发奖。可选undefined先规范化再签名，保证诊断重放一致。

`REWARD_RESULT.completed` 仅是测试端口输入。没有权限接入、SDK观察或服务端证明；可在开发控制台调用不代表能在生产信任客户端。

## 4. 洗牌与状态身份

前端测试用 `src/play/shuffle.js` 的拒绝采样+Fisher–Yates置换。默认随机源为开发用Math.random，不复用Node生成器，也不声称密码学随机；调用方可传入uint32源。实际图案序列随命令保存，重放不再调用随机函数。

旧 `shuffleRemaining` 检查置换多重集并计算牌面摘要。本轮给它传实际列表；暂存保持taken=true，不进入置换。session指纹另覆盖taken、rack、buffer、used、pending等，不把关卡快照hash当成完整局面身份。

## 5. 撤回与守恒

taken表示“离开原始棋盘/侧堆”，暂存和主槽都属于taken。撤回主区牌时回到原坐标，重新由父关系计算遮挡，不仅是从槽里减一个数字。

不变式：剩余主区/侧堆 + 主槽 + 暂存 + 已消除 = 原始总牌数；同一个ID只在一个活动区；已消除各图案均为三的倍数；稳定主槽不得残留三张同类。缓冲区有牌不能仅因主区已空而判胜。

## 6. 诊断记录而非新增续局玩法

导出包括初局、已接受命令及实际洗牌结果、最终指纹。导入逐条重执行并比对指纹；挂起领取仍保持挂起，不会自动发奖。重复领取的去重信息通过重执行重建。

目前仅供开发者排错，没有自动读取旧记录、没有“继续上次”玩家入口，没有云存档。checksum可由人重新计算，不是防作弊方案。日志限制10000个接受命令及约8M UTF-16代码单元输入，不把它称为网络字节限额。

## 7. UI与平台

`ui/play-app.js` 与微信目录里的同名文件逐字节相同。它只消费session操作结果，不在绘图回调决定消除或发奖。数字和控件是开发UI，首页只是测试入口，不替代P01原作完整首页。

本轮触摸仅接受单指，后台状态锁输入，前台回归不改变奖励结果；没有真实广告、分享或计时实现。

微信入口仅使用createCanvas、窗口信息、onTouchStart、onHide、onShow、onWindowResize（存在时）。官方类型来源在研究时重新打开：
https://raw.githubusercontent.com/wechat-miniprogram/minigame-api-typings/master/types/wx/lib.wx.api.d.ts

类型文件及接口桩不代表平台运行。真实微信、Android、iOS、Windows都尚未实测。
