# 指标口径与收入核对 v0.10

本文件是我方统计设计，不是《羊了个羊》后台数据，也不是会计确认政策。人民币示例只是输入算术；统计、预估、可结算、到账分开。

## 1. 三本独立记录

**行为记录**：玩家看到了什么、主动选择了什么、返回以后是否继续。**权益记录**：资格、观看结果来源、待兑现、兑现回执。**资金记录**：平台认可展示、预估净收入、已结算、现金到账、推广支出。三本用日期、广告单元、业务触点对照，但不可相互替代。

核心事件必须有 eventId、发生时间、接收时间、serverDayKey、appVersion、ruleVersion、placementId、adUnitId（存在时）、匿名会话/用户标识、roundId、attemptId、result状态、错误原码及已确认含义。未知错误保留 UNKNOWN，不编造“达到每日上限”。

采集不得含广告素材的点击坐标、通讯录、好友隐私、广告展示画面或不必要个人信息。来源query须白名单验证；公开分享链接不可放原始openid或可作为身份凭证的token。

## 2. 事件及去重口径

| 事件 | 唯一键/分母 | 不能偷换成 |
|---|---|---|
| game_enter | server visit/session | 新用户；必须按合规身份/去重规则识别 |
| round_start | roundId | 教学完成或一天活跃 |
| offer_view | 同一offerId初次可见 | 在后台预加载广告 |
| offer_accept | 同一offerId主动确认 | 广告展示 |
| ad_load_ok / ad_load_fail | attemptId+阶段 | 收入 |
| client_ad_presented | attemptId，SDK展示成功观察 | 平台有效/计费展示 |
| ad_completed_observed | attemptId，SDK明确isEnded=true及观察来源 | 服务端已验真/实际发奖 |
| grant_committed | claimId，事务成功 | 收入到账 |
| play_resumed | claimId后同局第一笔有效游戏操作 | 从后台回来/点关闭 |
| result_verified | roundId+结果版本 | 省份已经加分 |
| contribution_ack | resultId/业务范围 | 加载过一遍排行榜 |
| share_launch_requested | shareAttemptId | 分享完成 |
| referred_session | 合法query的进入会话 | 分享给了几个群/因果带来的全部新用户 |

服务器重试与离线补报按eventId去重。按数据接收时间判断统计完整性；若消息迟到，记录报表修订，不改写历史原始事件。SDK事件不必严格按时间顺序到达，漏斗按attempt关联，不用到达次序拼接。

## 3. 最小指标表

| 指标 | 公式 | 必须附带的限制 |
|---|---|---|
| 领取选择率 | 主动确认offer / 可见且可执行offer | 同一个offer多次绘制不重复加分母 |
| 客户端展示观察率 | 去重presentation / 发起attempt | 不是平台填充率的完全替代 |
| 观察完成率 | 明确completed / presentation | 无回调/跨日等待单列未决 |
| 兑现率 | grant_committed / completed | 以同一批attempt为队列；未结清单列 |
| 继续率 | play_resumed / grant_committed | 给每笔已到账样本同等观察窗口 |
| 每活跃用户净广告收入 | 同期平台净收入 / 合规去重DAU | 分平台、地区/渠道/新旧客；未完整期间注明 |
| 每千次展示净收入 | 平台净收入×1000 / 平台有效展示 | 净口径不要再乘平台分成 |
| 次日留存 | 某日首次有效进入、次业务日回访人数 / 当日新增人数 | 队列次日结束后才成熟；不拿小时留存替代 |
| D7留存 | 第7业务日回访 / 同一新增队列 | 完整观察窗口，不混滚动7日活跃 |
| 队列累计净收益 | 队列各日可归属净收入总和 / 初始新增数 | 报表无用户归因就标模型估计，不编逐用户精确收入 |
| 付费获客成本 | 同口径付费投放成本 / 可归因新增 | 自然新增不混入付费分母来压低成本 |

算法版本只作分析维度；同一局不根据广告观看量改牌。模拟策略通过率不是商业用户留存。

## 4. 资金报表合同

输入至少包括 periodStart、periodEnd、asOf、timezone、currency、sourceReportId、reportRevision、coverageStatus（partial/final）、metricBasis（gross/net）、platformImpressions、estimatedNetFen、settledNetFen、cashReceivedFen、adCreditBalance（独立维度）、paidTrafficFen、variableCostFen。

- 钱以整数分存储；展示数非负整数。收入调整可以是有记录的负数，禁止浮点元直接累加。
- `null`=资料缺失，`0`=报表真实为零。不能用0替代尚未公布收入，也不能分母为0时显示0%的假精度。
- 预估6000分、结算5000分、到账4000分代表不同状态；**不能相加成15000分**。
- 分成比例只在使用gross口径时由已核验协议输入。已是开发者净口径就不再乘50%等数字。
- 实际资金账按平台可结算和银行到账对照；SDK播放次数仅用于异常诊断。两者差异可来自期间、无效流量、平台修订等，原因须查证，不自动认定平台少付。
- 同一adUnitId复用于多个道具时，平台只有单元总收入就只能精确核对总额。按本地展示比例分摊只能叫估计；要准确比较触点，需符合平台条件的独立单元及一致期间。
- 现金、广告金/券分开；广告金不是银行到账。费用和税费按实际口径披露，不默认已经扣完。

示例（全部假设）：平台3000次展示、预估净收入6000分，则净eCPM=20元；已结算5000分、投放1000分、可变成本500分，则已结算口径贡献=35元；到账4000分单列40元。35元不是已扣全部固定成本和税的净利润。

## 5. 经营决策而非固定收益承诺

不要把60元/天等演算写成预算承诺。初步模型：

每日预估净收入 ≈ 活跃人数 × 人均平台有效展示 × 净eCPM / 1000。

付费渠道是否放量，比较同一队列、同一窗口的可归属净收入与获客及可变成本。D7收入不能比较另一个30天的成本；有大额自然传播时单独拆分，不用全站平均证明买量赚钱。

先观察小样本的兑现与退出路径；样本未成熟时不宣布ROI达标。不设置没有依据的“D1必须40%、每天4条”等原版指标。

## 6. 实验边界

本阶段默认不开改变原作机制的A/B实验。可先对加载稳定性、错误恢复、数据完整性做版本比较；玩家可见文案/布局/奖励变化需另确认。

若做经批准的实验，提前写清样本单位、主要指标、观察窗口、停止规则、广告/关卡配置；按用户或其他稳定单位分组，避免同一局中途换组。随机策略、模拟用户与真实流量完全分账。不得制造真实广告流量、诱导点击或拿自动化回放刷收益。

## 7. 日常核对流程

取平台当日可得报表并记asOf → 按业务日/广告单元重建本地展示与权益链 → 排查待兑现与重复事件 → 分开呈现预估/结算/到账 → 将迟到数据及平台修订作为新版本 → 等队列成熟再讨论留存、投放。

异常优先处理顺序：观看后没有兑现 → 旧局奖励误发新局/重复作用 → 展示观察与报表口径不一致 → 成本与收入不匹配。未知收入不显示红色亏损或绿色盈利。
