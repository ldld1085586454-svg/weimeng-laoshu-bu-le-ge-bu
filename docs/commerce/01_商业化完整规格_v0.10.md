# 2022 微信版《羊了个羊》商业化规格 v0.10

**日期：2026-09-18｜目标：2022年9月爆火时期微信版｜状态：商业规格及模拟验证，不是已上线商业版。**

## 0. 本次要解决的事

让已有消除与道具工程承接完整的“免费进入—遇到辅助需求—自愿领取—可靠兑现—继续挑战—真实展示—回访与收入核对”流程。v0.8 算法和 v0.9 游戏源文件不变，不因商业化重写算法、改变七格规则或增加新玩家系统。

本包交付商业规则、异常分支、数据口径、配置、实现任务及可运行流程演示。演示中的广告、权益到账和经营数据都是明确标注的模拟值；真实广告、服务端结算、地区数据与手机验收不在“已完成”范围。v0.9 牌局页保留，可独立运行；本轮商业演示尚未接管该页的会话。

标记：**H 历史记录**、**C 社区/既有工作候选**、**E 我方工程设计**、**U 待核事实**。E 不得写成“原作就是如此”；U 不能无提示地填入一个猜测数值。

## 1. 收费结构：玩家端不做现金价格表

| 事项 | 本项目决定 | 依据/性质 |
|---|---|---|
| 开始、正常取牌、重新挑战 | 不收现金，不插入充值门槛 | H：同期免费体验记录，H01/H02/H03 |
| 三个局内道具、失败后的复活入口 | 原有激励触点；取得机会与实际效果分开 | H：入口；细节按 C/U |
| 游戏商城、金币购买道具、会员、月卡、付费免广告、体力售卖 | 不在目标范围，不实现 | 版本范围约束；不是所有时期的永久结论 |
| 收入来源 | 当期以视频广告为主，收入接平台报表 | H01/H03 |
| 横幅、强制开屏、结算强制插屏 | 不自行增加 | H01 无横幅表述；其余为目标范围约束 |
| 玩家必须点击广告或下载广告内商品才发奖 | 不设置 | E：我们的奖励只绑定合法组件的观看结果，不引导虚假点击 |
| 分享 | 保留历史存在记录；现在上线路径另审核 | H02/P02/U |

广告主支付的投放金额不是我们的净收入；平台展示后的预估收入、可结算收入和到账现金也不是同一数值。用户得到的是一次明确的辅助，不是“看广告直接通关”。不承诺固定广告时长，不宣传稳定每条收入。

**四个业务触点不等于四次必然展示，更不等于四次必然计费。**玩家可以不领取、无填充、提前关闭，也可能遇到额度或平台限制。

## 2. 商业闭环及每一步的完成标准

| 阶段 | 玩家发生的事 | 商业目的（分析） | 完成证据 |
|---|---|---|---|
| 进入 | 免费打开、进入原有挑战 | 获得真实参与 | game_enter、round_start |
| 理解与投入 | 完成教学、进行主挑战 | 玩家知道道具有什么用 | tutorial_finish、有效取牌 |
| 辅助需求 | 自己点移出/撤回/洗牌，或进入失败页 | 承接当下需求 | offer_eligible、offer_view |
| 自愿选择 | 明确点观看视频或不用 | 判断领取意愿 | offer_accept/decline，不用点击广告素材衡量 |
| 广告与权益 | 请求、展示、完整关闭、处理权益 | 自愿变现与可靠兑现 | 四个独立事件链；不能合并为一个success |
| 继续 | 道具作用后进行有效取牌 | 判断帮助是否有价值 | assist_applied 后同局首次合法 pick |
| 结果 | 通关/失败，结果向我方服务提交 | 真实社交展示与回访 | result_verified、contribution_ack |
| 后续 | 再挑战、分享入口、次日回访 | 看留存与传播 | 有效进入/成熟队列留存，不把返回前台算分享成功 |
| 核算 | 平台报表更新、结算、到账 | 检验经营可持续性 | 报表期间、版本、币种、口径、来源 |

这不是新增玩家模式。指标页、调试开关、证据回放只出现在开发演示，不进入正式游戏。

## 3. 四个触点的产品规格

### 3.1 移出：move

- 入口：原局内道具按钮。文案表达“移出槽内前三张，仍需稍后消除”，不写“删除三张”。H/C。
- 打开领取前检查：本局仍在进行、槽内至少三张、既有工作候选要求暂存为空、该道具本局仍有次数、没有挂起领取。C/E。
- 获得资格后：按当前槽序执行前三张移出；棋盘结果与次数在同一业务提交中更新。E；不是广告开始时先扣一次。
- 奖励没有真正作用前不能显示“已使用”。不临时改为自由选三张，不附赠洗牌。

### 3.2 撤回：undo

- 入口：原撤回按钮，不用“不看视频就丢失全部进度”之类误导语。
- 采用 v0.9 候选边界：最近一次未形成三消的主区取牌；上一步三消不恢复整组。侧堆与暂存来源仍未绑定。C/U。
- 必须先确认确有可撤回对象，再请求广告。对不可执行局面，用明确原因返回，不让玩家先看完再报错。
- 领取期间不接受新的棋盘操作。结果绑定准备时的 boardRevision 和 tileId；不能撤回广告后另一笔新取牌。E。

### 3.3 洗牌：shuffle

- 原入口存在。当前候选只置换主区和未取侧堆的图案，保留槽、暂存、位置、图案总量。C。
- 不把“重排”宣传成“保证有解/保证通关”，不因观看记录调整成功概率，不反复重排到最有利结果。
- 事先生成/检查作用计划，成功提交时记录实际置换及快照标识。异常恢复使用同一结果，不能重抽。E。

### 3.4 复活：revive —— 商业上重要，但不能写一个假的效果

- 原失败后存在一次复活机会的同期记录；进入失败、出现复活选择、拒绝后重开，是应还原的流程。H。
- **当前未决：复活到底移出/消除哪些牌，与已有暂存、移出次数如何互动。**原始截图、同期描述与社区实现未完全对齐。U。
- 前端应准备“复活/重新挑战/退出”状态以及取消、广告失败、权益处理中分支；但实际复活效果未绑定之前，不产生可观看的真实广告请求。
- `effectBound:false` 是发布阻断，不是把复活永久删除。完整商业化验收必须关闭这个缺口；当前包不能被标为“复活已开发完成”。
- 绑定模板必须填写：证据编号、来源日期/平台、牌区变化、顺序、次数关系、已有暂存行为、操作日志样例及边界测试。不能用“最合理”替代来源。

## 4. 界面/操作合同（中文是实现文案，不声称逐字复原原图）

| 状态 | 主操作 | 其他操作/提示 | 禁止行为 |
|---|---|---|---|
| 可用道具详情 | 观看视频并使用X | 不使用/关闭，保留当前局 | 未点击就自动拉起广告 |
| 正在加载 | 状态提示 | 加载失败可返回/手动重试 | 不限次数自动请求、假倒计时催促 |
| SDK展示 | 由官方组件管理 | 游戏不截获或伪造关闭按钮 | 要求点素材或下载才能领奖 |
| 提前关闭 | 不发本次奖励 | “未完成观看，本次未使用道具” | 扣已用次数、偷偷换到分享 |
| 无广告/失败 | 保留原局/已失败状态 | 再试一次、继续不使用、重新挑战 | 自动改成充值、假装完成 |
| 观看完成待兑现 | 正在处理 | 重试兑现/查询，不再看一次广告 | 要求再次观看来领取已取得机会 |
| 作用已提交 | 返回原局 | 继续操作 | 重复回调再给一次 |
| 失败页 | 有效时复活 | 免费重开/返回 | 把免费重开藏掉或强制看广告 |
| 胜利页 | 展示真实局内结果 | 贡献同步状态、原有展示/分享入口 | 服务未确认即伪造省份加分 |

## 5. 领取流程与不丢权益

工程状态：OFFERED → LOADING → READY → SHOWING → EARNED_PENDING → APPLIED → RESUMED。

- `SHOWING` 只代表客户端观察到组件展示，不代表平台已计费。
- 官方 onClose 的 `isEnded` 指是否完整观看关闭（P01）。仅 `true` 进入完成证据处理；false=未完成；字段缺失=未核定，不用“undefined也成功”的旧式兼容兜底。
- `EARNED_PENDING` 是待处理记录，不是发明一个可跨局使用的新货币/背包道具。
- 发奖出错进入 `RECOVERY_REQUIRED`，保存原attempt/round/revision和应有作用；重试的是同一笔兑现，不是重新播放广告。
- 已重开新局时，旧奖励不能改新棋盘。应保留原局待处理记录和诊断路径；是否恢复原局必须遵守已确认的续局规则。不能静默转成跨局道具或声称“补发完成”。
- 原局数据不可恢复时，展示明确的处理状态，交由已审核的补救流程；这是必须在真实发行前验收的问题，不以本地模拟遮盖。
- 服务端用唯一attemptId/claimId去重；同ID不同载荷拒绝。状态变更、次数变更、结果日志同事务提交；客户端重试不得重复结算。
- 客户端回调不是服务端不可伪造的观看证明。平台若提供适用的服务端校验，以实际官方能力接入；没有时，要明确标记client_evidence并做我方重放/风控，不能把字符串token当鉴权。

## 6. 次数、日界线与运营参数

| 计数 | 本版处理 |
|---|---|
| 本局 move/undo/shuffle 使用 | 沿用 v0.9 各1次工作候选；模拟作用成功后扣 |
| 本局 revive | 字段1；效果未绑定，不开放请求 |
| 开发者自设每日上限 | null：未配置，不是0，也不是证明官方无限 |
| 平台对账户/广告库存的上限 | 未获得准确当前值；按可识别结果处理，不从报错推算 |
| 分享替代观看的阈值 | 未知；历史记载留档，不写死失败N次或观看N次 |

采用我方业务日 Asia/Shanghai，服务端给出 dayKey；不跟随玩家手机时区。领取锁定开始时规则版本、业务日、原对局；跨零点时完成事件记录实际发生日，使用资格仍归属原对局/原领取日。这是工程方案，不是原作午夜行为结论。

运营可以停用广告、关闭异常广告单元、回滚配置。不能在对局中修改牌面来追广告收益；不能悄悄增加道具次数、额外复活或商城。调整原作可见行为必须回到版本证据与用户确认。

## 7. 历史分享与当下平台要分开

H02 有分享获取道具的历史体验记录，但准确触发参数未公开。本轮能读取 P02：普通 `shareAppMessage` 参数没有分享完成回调；onShow/getLaunchOptions中的query用于识别进入来源，不等于发送者已完成分享。

P01 的 `CreateRewardedVideoAdOption` 还有 `disableFallbackSharePage`（标注3.7.7起），说明**官方广告组件自己的分享页与我们自行添加的分享奖励不是同一个入口**。不能见到这个参数就断言2022年原作用了该能力，也不能把分享页返回计为一个视频广告展示。

本轮访问部分当前官方运营页面失败，未完整核实分享奖励条款、开通阈值、分成比例。因此采用保守发布配置：`shareRewardEnabled:false`，组件分享页初始设为禁用，实际版本支持须真机确认；普通自愿分享和来源分析可按当前正式能力接入。历史通道保留为需要复核的差异，不称为“历史一比一已上线”。

## 8. 通关、地区贡献、装扮与再次进入

地区、话题、好友、荣誉、装扮是既有范围；商业分析把它们视为挑战结果展示与回访场景，不扩展属性养成、聊天、公会或实时对战。

1. 局内严格清空验证后可立即显示本局胜利。
2. 向我方服务提交roundId、规则/牌局版本、必要的动作证据。服务验证后返回resultId和可展示的贡献结果；不连接原作私有服务器。
3. 相同round重复提交只返回已有回执。地区计分、称号资格、同日重复通关怎么计数，必须独立绑定历史规则；不把“每次+1”当默认真相。
4. 网络失败显示“本局通关，贡献待同步”，不能显示假的已加分，也不能发明“看广告才能同步成绩”。
5. 无后台/无用户时显示未接入或暂无已验证数据，不生成假在线人数、假朋友记录。
6. 分享展示真实结果，不强迫分享才能关闭结算。回访按原每日挑战结构，不新增签到、转盘、充值礼包。

## 9. 收入与数据：必须能追查，而不是凭感觉调难度

详见《02_指标口径与收入核对》。最小闭环包含：看到道具机会、主动领取、客户端展示观察、完整观看证据、实际作用、继续有效操作、重开/结果、队列回访、平台报表。

主指标不是“每局塞满四条广告”。判断优先级：兑现可靠 → 玩家能继续 → 实际平台净收入 → 留存及获客成本。任何变更同时记录规则版本和布局版本，避免把变难、广告库存、节假日等影响混为同一原因。

不把同一用户多次领奖当新增用户，不把分享返回当新访客，不把未满一天的队列记为次留0。广告现金和推广广告金分账，不将券计作可提现收入。

## 10. 开发与发布完成标准

本包完成的是规格、模拟模型和演示，当前生产开关关闭。上线前必须具备：合法自有主体与可用AppID/广告单元、当前平台条款复核、复活及其边界绑定、真实广告返回验证、我方事务与去重、隐私告知及所需授权、真实结果服务、Android/iOS真机验收、至少一次平台报表核对。是否需要具体证照及流程，以适用当前规则核验，不使用“只有广告所以不需要审核”的推论。

素材、名称、音乐和品牌的授权另列发行清单；社区代码许可不等于这些素材都可商用。本包不复制官方美术、账号或服务端身份。

研究、联调、平台接入、商业发行分层验收。没有后台现金数据，就说“尚未核算”；没有真机，就说“模拟通过”。不把发布阻断藏在一份“完整游戏”标题下面。
