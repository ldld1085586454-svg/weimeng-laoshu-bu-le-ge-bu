# 全模块交付与验收 · v0.12

日期：2026-09-18。交付类型：**可运行的全模块开发工程，非正式发布版，也不是原作完整像素级复刻完成证明。**

## 1. 交付结论

前面两份v0.11的差异已统一：以最后一份“对局领取整合开发版”为底，保留它的全部20个旧src文件；另一份已交付的候选复活进入新增 `src/product/` 命名空间，不覆盖旧内核。本版只有一个主产品入口：`全模块游戏_双击打开.html` / `wechat_full/`。

首页、实际棋盘、奖励领取、候选复活、胜负结算和社交记录已经连接到同一组状态。真实广告/好友/游戏圈适配代码已写入，但对应平台资格、真实基础库及真机行为还没有通过实测。生产后端不是完成项。

## 3. 本轮真实验证结果

### 自动化回归

`node tools/check-full.js` 已运行：**300项Node测试通过，0失败、0跳过**。其中234项为继承回归，66项为新增产品、界面、服务、原生适配、构建与交付测试。

原v0.8的**12个算法文件**逐字节不变；**包含它们在内的20个旧src文件**也全部与采用的v0.11基线SHA-256一致。不是“12+20个互不重叠的文件”。

原生入口测试是在Node中用模拟wx对象执行实际入口脚本；它验证调用衔接、触摸、前后台、坐标偏移和开放数据域晚回调隔离，**不等价于微信实机运行**。

日志：`reports/product/final-node-validation.txt`。

### 浏览器实际输入

`python tools/full-browser-qa.py` 已运行：**35组检查通过，0未捕获页面异常，保存21张最终截图**。覆盖首页11个入口、历史切换、预设弹幕、12次教学点击、教学进入每日、分享撤回、视频提前关闭、270次实际鼠标点击通关、已解锁换装、移出暂存、复活保留原暂存且继续通关、原笔领取重试、第二次失败、免费重开、后台输入隔离及四种视口。

视口：320×568、390×844、430×932、1280×900。另有Node短屏与原生安全区回归。

**环境限制：**浏览器策略以 `ERR_BLOCKED_BY_ADMINISTRATOR` 拒绝了 `http://127.0.0.1` 和 `file://` 导航。因此浏览器测试使用 `set_content` 载入构建后完整自包含HTML，再执行真实指针输入；不是直接双击HTML，也不是通过浏览器实际访问Node服务。HTTP服务另外通过Node测试发起真实HTTP请求，执行270步通关日志提交与重复提交。不能把两层测试相加说成真实微信/Windows/生产环境全链路已验收。

记录：`reports/product/browser-qa.json`、`navigation-probe.json`；图像位于同目录。早期修复前截图仅保留在 `diagnostic-before-fix/`。
