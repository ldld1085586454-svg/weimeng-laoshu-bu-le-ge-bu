# 正式素材替换指南

浏览器和微信小游戏共用 `assets/theme/manifest.json`。该清单只覆盖列出的素材，实际角色使用根目录主题清单配置的新图集，包括已批准的首页、胜利与荣誉角色。空清单或运行时素材错误时的矢量回退是加载器的兜底机制，可以先替换一张图，再逐步补齐整套素材。

`docs/product/asset-manifest.json` 是现有素材来源记录，不是主题加载清单。

## 文件与清单

将图片放入 `assets/theme/`，使用项目内的相对路径。推荐透明 PNG，角色、方块符号和图标应保留透明边缘。构建支持 PNG、WebP、JPEG，检查文件头与扩展名是否一致；不接受文本占位图或跳出该目录的路径。WebP 交付前须在实际微信运行环境验证解码和透明度表现。

建议尺寸：牌面符号256×256、角色512×512、功能图标96×96、方块底板256×256。背景可按390×844的两倍尺寸制作，短屏和不同宽高会居中裁切。符号及角色按比例完整显示；底板填充实际牌框，请把需要的描边与阴影做进图片，成功替换后不再叠加旧底板。

```json
{
  "schema": 1,
  "assets": {
    "background.home": { "src": "assets/theme/home.png" },
    "character.plain": { "src": "assets/theme/sheep.png" },
    "tile.T00": { "src": "assets/theme/carrot.png" },
    "icon.undo": {
      "src": "assets/theme/icons.png",
      "rect": { "x": 64, "y": 0, "w": 64, "h": 64 }
    }
  }
}
```

每项必须提供 `src`。单张图片省略 `rect`；图集切片使用 `rect`，其中 `x`、`y`、`w`、`h` 都是图片原始像素单位，切片必须完整位于图片内，宽高须大于零。多个键可以引用同一张图集。

## 开发接口

共享素材加载器提供 `createArtAssets(manifest, { createImage, timeoutMs = 10000 })`。调用方注入平台的图片工厂。

`createArtAssets` 只处理 `assets`，不加载字体；`ready` 的结果也不包含字体加载状态。可选标题字体由构建流程和宿主管理，清单 `schema` 仍为 `1`，`fonts` 目前仅支持 `heading`：

```json
{
  "schema": 1,
  "assets": {},
  "fonts": {
    "heading": {
      "src": "assets/theme/fonts/ZCOOLKuaiLe-Regular.ttf",
      "family": "ZCOOL KuaiLe"
    }
  }
}
```

`src` 必须是 `assets/theme/` 内的 `.ttf` 或 `.woff2` 文件，建议统一放入 `assets/theme/fonts/`。`family` 为 1 至 100 个字符，只允许字母、数字、空格、下划线、点或连字符，且不能带首尾空白。构建检查字体文件头；缺失文件、错误格式、无效字体配置或目录逃逸会中止构建，不作为运行时兜底处理。

构建将浏览器字体内联为 `@font-face`，浏览器宿主最多等待 3 秒加载，失败或超时后使用系统字体。微信清单 `data/art-manifest.js` 保留字体文件路径，字体复制到 `wechat_full/assets/theme/`；原生宿主在 `wx.loadFont` 可用时加载，并使用其返回的字体名，加载失败时使用系统字体。字体格式兼容性与实际中文字形仍须在微信运行环境检查。

| 接口 | 行为 |
| --- | --- |
| `ready` | Promise；返回 `{ loaded: ['键名'], failed: [{ key: '键名', reason: '失败原因' }] }`，顺序沿用清单。单项失败不会使整个 Promise 拒绝。 |
| `get(key)` | 返回只读描述对象 `{ image, rect, width, height }`；宽高为该切片的原始尺寸。清单省略切片时，描述对象的 `rect` 为整图矩形，宽高为整张图片尺寸。素材不可用时返回 `null`。 |
| `draw(ctx, key, x, y, w, h, options)` | 在指定区域绘制，成功返回 `true`；不可用时返回 `false`，调用方继续矢量回退。 |
| `dispose()` | 结束使用并清理加载器资源，切换主题或销毁界面时调用。 |

`options` 默认为 `{ fit: 'contain', alpha: 1 }`：

- `contain`：保持比例，完整显示，区域内可能留白。
- `cover`：保持比例，填满区域，超出部分裁切。
- `stretch`：直接填满区域，可能变形。
- `alpha`：乘以画布当前的 `globalAlpha`，用于保留已有禁用或淡出效果。

`alpha` 范围为 0 至 1。相同 `src` 只预加载一次；图片尺寸优先取 `naturalWidth`、`naturalHeight`，微信等图片对象可使用 `width`、`height`。加载器检查图集范围，绘制时使用 `save()` / `restore()` 保留画布状态。

排查 `failed` 时，`IMAGE_ERROR` 表示加载或解码失败，`TIMEOUT` 表示超过默认 10 秒等待，`INVALID_RECT` / `RECT_OUT_OF_BOUNDS` 表示切片无效，`UNKNOWN_KEY` 表示键名不在上述列表。销毁后尚未完成的加载记为 `DISPOSED`，晚到回调不会重新写入缓存；此时 `get()` 返回 `null`，`draw()` 返回 `false`。

浏览器示例（`manifest` 为同一主题 JSON 的内容）：

```js
const assets = createArtAssets(manifest, {
  createImage: () => new Image(),
  timeoutMs: 10000,
});
const result = await assets.ready;
console.log(result.loaded, result.failed);
if (!assets.draw(ctx, 'tile.T00', x, y, width, height, { fit: 'contain' })) {
  drawVectorCarrot(ctx, x, y, width, height);
}
// 界面销毁时：assets.dispose();
```

微信小游戏使用原生图片工厂，其余清单和绘制调用一致：

```js
const manifest = require('./data/art-manifest'); // npm run build 生成的微信清单
const assets = createArtAssets(manifest, {
  createImage: () => wx.createImage(),
  timeoutMs: 10000,
});
await assets.ready;
```

## 打包与检查

更新清单和图片后运行 `npm run build`，构建将网页图片内联，并按同一清单复制图片到 `wechat_full/assets/theme/`、生成 `wechat_full/data/art-manifest.js`。浏览器不依赖单独图片请求；只需要交付生成的HTML。重新构建会清理不再被清单引用的微信主题图片。

构建前路径不存在、文件格式错误或目录逃逸会中止构建，保留上一份网页入口。运行时解码失败、平台图片接口失败、超时或图集切片越界才触发矢量兜底。可通过加载器的测试图片工厂模拟运行时加载失败，检查兜底；不要把缺失文件当成可成功构建的清单。检查首页、棋盘、角色、图标以及方块禁用状态，图集逐个检查切片边界，背景检查裁切后的主要内容是否可见。

浏览器检查通过后，还须在微信开发者工具和实际设备检查路径、图片解码、透明边缘与显示比例。这份指南不代表已完成微信设备验证。
